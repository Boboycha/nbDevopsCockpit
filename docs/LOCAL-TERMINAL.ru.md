# Локальный терминал

`TnbTerminalControl` поддерживает локальную командную оболочку. Для локальных
и SSH-сессий используются общие ANSI-парсер, буфер, отрисовка, обработка ввода
и темы оформления.

В демо есть кнопка **Local terminal**. Перед переключением между SSH
и локальным режимом отключите текущую сессию. Кнопка отключения завершает
сессию любого из этих типов.

## Использование

```pascal
uses
  System.SysUtils, System.Classes, FMX.Forms, Terminal.Control;

procedure TMainForm.OpenLocalTerminal;
begin
  // Windows: Windows PowerShell. Linux/macOS: $SHELL, при отсутствии — /bin/sh.
  TerminalControl1.StartLocalSession;
end;

procedure TMainForm.CloseLocalTerminal;
begin
  TerminalControl1.StopLocalSession;
end;
```

Чтобы задать исполняемый файл, массив аргументов и рабочий каталог:

```pascal
{$IFDEF MSWINDOWS}
TerminalControl1.StartLocalSession('cmd.exe', ['/d'], 'C:\Work');
// Или полный путь к pwsh.exe с аргументами ['-NoLogo'].
{$ELSE}
TerminalControl1.StartLocalSession('/bin/bash', ['-i'], '/tmp');
// Для macOS: /bin/zsh с аргументами ['-i'].
{$ENDIF}
```

Аргументы передаются отдельными значениями массива. Не собирайте из них строку
команды с заранее расставленными кавычками. В POSIX-системах путь к исполняемому
файлу должен быть абсолютным. Рабочий каталог должен существовать. Пустое значение
выбирает домашний каталог пользователя; явно указанный каталог имеет приоритет.
При пустом массиве аргументов в POSIX используется `-i`. Оболочка Windows
по умолчанию показывает стандартное приветствие и загружает профиль пользователя.
Сам профиль может изменить приглашение командной строки или рабочий каталог.
Локальные процессы запускаются с правами приложения, содержащего терминал.

До первого запуска `LocalSession` равен `nil`. После запуска через него доступны
`Running`, `SendText`, `OnExit` и `OnError`. Контрол владеет объектом сессии
и освобождает его: не освобождайте его самостоятельно и не заменяйте обработчик
`OnReadData`. Для наблюдения за выводом или его фильтрации используйте
`OnHostOutput`. Присваивание ненулевого `SSHClient` останавливает локальную сессию.
Попытка запустить локальную сессию при установленном или устанавливаемом
SSH-соединении вызывает исключение.

Для работы без визуального контрола создайте `TnbLocalTerminalSession` из модуля
`Terminal.LocalSession`, назначьте `OnReadData` и регулярно вызывайте `Pump`
в потоке, которому принадлежит сессия. `OnExit` передаёт код завершения процесса
или `-1`, если код недоступен. Явный вызов `Stop` не вызывает `OnExit`.
Методы `Start`, `Stop`, `SendText`, `ResizePTY`, `Pump` и обработчики событий
должны выполняться в одном потоке. Не уничтожайте сессию из её обработчиков
событий. Рабочие потоки не используют синхронные вызовы UI и не ставят в очередь
UI обратные вызовы.

## Реализация по платформам

- **Windows 10 1809+ / Windows Server 2019+:** ConPTY, каналы с данными в UTF-8
  и объект заданий Windows (job object), объединяющий оболочку и её дочерние
  процессы. Отдельное окно консоли не создаётся.
- **Linux:** `openpty` из libutil, новая сессия с управляющим терминалом,
  `execve` и `TIOCSWINSZ`. Для компоновки подключите libutil через SDK платформы.
- **Настольная macOS на Intel и Apple Silicon:** `openpty` из libSystem,
  тот же жизненный цикл POSIX-сессии и вызов ioctl для изменения размера окна
  в Darwin. Приложение с App Sandbox должно отдельно учитывать ограничения
  песочницы на запуск процессов.
- **Мобильные платформы:** код компилируется, но при вызове `Start` выдаётся
  явная ошибка о неподдерживаемой платформе.

В POSIX дочерние процессы получают `TERM=xterm-256color` и `COLORTERM=truecolor`.
Остальные переменные окружения наследуются. Буферы аргументов и окружения
подготавливаются до `fork`. Дочерний процесс сбрасывает настройки сигналов,
связанных с терминалом, закрывает унаследованные файловые дескрипторы
и до `exec` выполняет только нативные операции.

Чтение и запись выполняются в отдельных рабочих потоках. Размер каждой очереди
ограничен 4 МиБ. При заполнении очереди вывода чтение приостанавливается,
создавая обратное давление на источник данных. Ввод, превышающий свободное
место в очереди, отклоняется до добавления, а не обрезается без уведомления.
За один вызов `Pump` обрабатывает не более 256 КиБ и сохраняет незавершённые
UTF-8-последовательности между блоками.

При закрытии ConPTY поток чтения продолжает работать, чтобы принять последний
кадр вывода. В POSIX `Stop` завершает активную группу процессов терминала
и группу оболочки, получает статус завершения оболочки через ожидание дочернего
процесса и закрывает PTY. Процессы, намеренно отделившиеся в другую сессию,
этому терминалу не принадлежат. Приложение не должно самостоятельно забирать
статус завершения дочернего процесса этой сессии, например глобальным
обработчиком `waitpid(-1, ...)`.

## Проверка

`tests/LocalTerminalSmoke/LocalTerminalSmoke.dpr` проверяет интерактивный
ввод и вывод, изменение размера PTY, код завершения, повторные запуски
и остановки, закрытие при наличии ввода в очереди или непрочитанного вывода,
а также освобождение ресурсов при неверном пути к исполняемому файлу.
В Windows дополнительно проверяются кириллица и emoji через реальный канал
вывода ConPTY. Собирайте тест Delphi-компилятором из каталога теста.
Исполняемые файлы, DCU и объектные файлы направляйте
в `bin/local-smoke/<platform>`.

`LocalTerminalVisual.dpr` проверяет терминал в работающем FMX-приложении.
Он запускает локальную оболочку, выводит цветной маркер, изменяет размер формы,
сохраняет `local-terminal.png` рядом с исполняемым файлом и закрывает сессию.
Добавьте `src`, Synapse и FMX RTL в путь поиска. Развёртывание Skia выполняется
так же, как для обычного демо.

В этой рабочей копии выполнены следующие проверки:

- **Windows x64:** сборка пакета и демо, набор консольных проверок,
  получение изображения работающего FMX-терминала с PowerShell, цветным выводом
  и изменённым размером.
- **Linux x64:** набор консольных проверок, собранный Delphi и запущенный
  в локальной Ubuntu WSL.
- **macOS Intel и Apple Silicon:** компиляция обоих новых модулей.
  Запуск и компоновку с macOS SDK ещё необходимо проверить на Mac.
- **Существующий `TerminalBufferSmoke`:** пройден.

Перед выпуском проверьте на целевых настольных ОС интерактивные приложения
(PowerShell/PSReadLine, bash, zsh, vim/top), Ctrl+C, Ctrl+D, Tab, AltGr,
выделение, вставку из буфера обмена, передачу событий мыши, альтернативный
экранный буфер и повторное закрытие окон. Автоматические проверки не подтверждают
полное соответствие терминальным стандартам.

Источники: [жизненный цикл ConPTY](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session),
[ограничения fork и exec](https://man7.org/linux/man-pages/man2/fork.2.html).
